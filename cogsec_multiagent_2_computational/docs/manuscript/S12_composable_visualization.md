# Supplement S12: Composable Visualization Engine {#sec:composable-visualization}

> **Purpose.** This supplement documents the static composable visualization
> classes in `src/visualization/composable.py`, which render the categorical
> structures of §\ref{sec:category-theoretic-foundations} and the CIF defense
> pipeline as ASCII or SVG. A separate data API,
> `visualization.composer_data.get_composer_data()`, is exported by
> `scripts/generate_composer_data.py` to `output/data/composer_data.json`.
> No interactive web UI, event handling, or animation is shipped.

## Overview {#sec:viz-overview}

The visualization engine exposes six diagram types, each corresponding to a
formal structure from §\ref{sec:category-theoretic-foundations}:

| Component | Formal structure | Section |
|---|---|---|
| `DefenseGraph` | Morphism graph in $\mathbf{Def}$ | §\ref{sec:monoidal-category} |
| `CategoryDiagram` | Full category diagram with composition paths | §\ref{sec:monoidal-category} |
| `LatticeViz` | Detection-rate lattice $\mathcal{L}_\text{def}$ | §\ref{sec:defense-lattice} |
| `OperadPlot` | Operad composition tree (series and parallel) | §\ref{sec:operad} |
| `MonadFlow` | Kleisli pipeline of the defense monad $\mathbb{T}$ | §\ref{sec:pipeline-monad} |
| `LensDiagram` | Attack-defense profunctor optic | §\ref{sec:lens-optic} |

{#tab:viz-components}

## Diagram Types {#sec:viz-diagram-types}

### DefenseGraph

`DefenseGraph` renders the directed graph of CIF defense morphisms with
edges labelled by detection rate $\mathrm{DR}(f) \in [0,1]$.  Node colour
encodes the defense layer (Input, Isolation, Monitoring, Coordination).
Edge width is proportional to $\mathrm{DR}(f)$.

### CategoryDiagram

`CategoryDiagram` stores objects with fixed coordinates and labelled morphism
arrows, then renders them with `to_ascii()` or `to_svg_string()`. Its builders
supply static unitor, associator, monad, and Kan-extension diagrams; composition
paths and commutativity witnesses are shown as labels and arrows rather than
selected through a user interface.

### LatticeViz

`LatticeViz` draws a static Hasse diagram of $\mathcal{L}_\text{def}$, ordered
by the detection rates supplied to its nodes. Node labels include those rates;
the renderer uses fixed coordinates and provides no hover or drag behavior.

### OperadPlot

`OperadPlot` accepts a list of defense identifiers through
`build_series_tree()` or `build_parallel_tree()` and renders the resulting
planar or branching composition tree as static ASCII or SVG. There is no input
panel or live-update interface.

### MonadFlow

`MonadFlow` renders a static left-to-right Kleisli pipeline. Labelled stages
include the unit $\eta$, each defense morphism, and join $\mu$; the SVG and
ASCII outputs contain no animation.

### LensDiagram

`LensDiagram` renders a static attack-defense optic
(§\ref{sec:lens-optic}), including the *get* and *set* actions, defense rate,
and lens-law labels. Lens composition is a data/formal operation elsewhere in
the framework, not a button-driven rendering feature.

## CIF Composer Data Pipeline {#sec:cif-composer}

The composer data is generated by `scripts/generate_composer_data.py` into
`output/data/composer_data.json`. `get_composer_data()` returns a
JSON-serialisable dictionary containing module metadata, composition formulas,
preset configurations, and optional category-theory results. This data export
is independent of the static rendering classes above; it does not supply an
event-driven UI. Its measured module rates come from the capability artifact:

```
output/data/
  composer_data.json             ← exported topology, formulas, presets, and rates
  module_capability_matrix.json  ← 1,475 attacks + 120 benign; per-module measurements
```

The static renderers and JSON exporter can be used independently. Neither one
implements browser interaction or animation.

## Reproducibility {#sec:viz-reproducibility}

All composer data are regenerated deterministically from the evaluation outputs:

```bash
# Regenerate composer data
python scripts/generate_composer_data.py
```

Cross-references between this supplement and the main text are maintained by
the figure registry (§\ref{sec:category-theoretic-foundations}); every `{#tab:...}` and
`{#fig:...}` label in this file is tracked in `output/data/figure_registry.json`.
