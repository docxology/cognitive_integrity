# Supplement S12: Composable Visualization Engine {#sec:composable-visualization}

> **Purpose.** This supplement documents the composable visualization engine
> that renders the categorical structures of §\ref{sec:category-theoretic-foundations}
> and the CIF defense pipeline as interactive diagrams. The engine is
> implemented in `scripts/generate_composer_data.py` and deployed as the
> **CIF Composer** web application at `output/web/cif_composer_v2.html`.

## Overview {#sec:viz-overview}

The visualization engine exposes six diagram types, each corresponding to a
formal structure from §\ref{sec:category-theoretic-foundations}:

| Component | Formal structure | Section |
|---|---|---|
| `DefenseGraph` | Morphism graph in $\mathbf{Def}$ | §\ref{sec:monoidal-category} |
| `CategoryDiagram` | Full category diagram with composition paths | §\ref{sec:monoidal-category} |
| `LatticeViz` | Detection-rate lattice $\mathcal{L}_\text{def}$ | §\ref{sec:defense-lattice} |
| `OperadPlot` | Operad composition tree (series and parallel) | §\ref{sec:operad} |
| `MonadFlow` | Kleisli pipeline of the defense monad $\mathbb{T}$ | §\ref{sec:pipeline-monad} |
| `LensDiagram` | Attack-defense profunctor optic | §\ref{sec:lens-optic} |

## Diagram Types {#sec:viz-diagram-types}

### DefenseGraph

`DefenseGraph` renders the directed graph of CIF defense morphisms with
edges labelled by detection rate $\mathrm{DR}(f) \in [0,1]$.  Node colour
encodes the defense layer (Input, Isolation, Monitoring, Coordination).
Edge width is proportional to $\mathrm{DR}(f)$.

### CategoryDiagram

`CategoryDiagram` extends `DefenseGraph` with composition paths: clicking
a sequence of morphisms renders the composed morphism and its combined
detection rate (series: Theorem 3.1 \cite{friedman2026cogsec1}; parallel:
Theorem 3.2 \cite{friedman2026cogsec1}). The diagram highlights commutativity
witnesses (pentagon/hexagon cells) from the symmetric monoidal structure
(§\ref{sec:monoidal-category}).

### LatticeViz

`LatticeViz` draws the Hasse diagram of $\mathcal{L}_\text{def}$ for a
selected subset of defenses.  Hovering a node displays the empirical detection
rate across the 950-attack corpus; dragging nodes reorganises the layout while
preserving the order relation.

### OperadPlot

`OperadPlot` renders composition trees as planar trees (series) or rooted
DAGs (parallel).  The input panel accepts a list of defense identifiers;
the plot updates in real time to show the combined detection rate and the
operadic normal form (fully left-associated series tree).

### MonadFlow

`MonadFlow` animates the Kleisli pipeline: a cognitive state $\sigma$ enters
at the left, passes through each defense morphism (rendered as a labelled
node), and exits at the right as the post-defense state $T(\sigma)$.  The
unit $\eta$ (no-op) and join $\mu$ (pipeline flatten) are shown as special
edges.

### LensDiagram

`LensDiagram` renders the attack-defense lens optic
(§\ref{sec:lens-optic}).  The left half shows the *get* (observe) action; the
right half shows the *set* (manipulate) action and the defense optic
interception.  Clicking the "compose attacks" button stacks two lenses and
displays the corresponding composed optic.

## CIF Composer Web UI {#sec:cif-composer}

The CIF Composer (`output/web/cif_composer_v2.html`) is a self-contained
single-page application generated by `scripts/generate_composer_data.py`.
It bundles all six diagram components and connects them to live data from
`output/data/`:

```
output/data/
  figure_registry.json          ← figure/table auto-numbering (§ 8)
  composer_data.json            ← pre-computed graph topology and DR values
  full_evaluation_results.json  ← per-module detection rates (empirical)
  ablation_results.json         ← ablation contributions (§ 5d)
```

The web UI requires no server — open `output/web/cif_composer_v2.html` in any
modern browser.  Select defense modules in the left panel; the right panel
updates all six diagrams simultaneously.

## Reproducibility {#sec:viz-reproducibility}

All diagram data are regenerated deterministically from the evaluation outputs:

```bash
# Regenerate composer data
python scripts/generate_composer_data.py

# Re-open the UI
open output/web/cif_composer_v2.html
```

Cross-references between this supplement and the main text are maintained by
the figure registry (§\ref{sec:category-theoretic-foundations}); every `{#tab:...}` and
`{#fig:...}` label in this file is tracked in `output/data/figure_registry.json`.
